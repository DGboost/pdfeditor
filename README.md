# DocEdit — 브라우저 문서 편집기

PDF, DOCX, HWP, HWPX, PPTX를 같은 파일 선택 화면과 공통 헤더에서 엽니다. 문서 처리는 브라우저 안에서 수행하며 Office 엔진은 자체 호스팅 same-origin iframe으로 분리합니다. iframe은 UI·입력 상태의 격리 경계이지 보안 샌드박스가 아닙니다. 구형 DOC/PPT는 직접 편집하지 않으며 DOCX/PPTX로 변환한 파일이 필요합니다.

기존 PDF 편집은 MuPDF **1.28.1**을 사용합니다. PDF에 새 텍스트·이미지·서명·사각형을 삽입하거나 형광펜을 추가하는 기능은 제공하지 않습니다.

## 실행 및 검증

Node.js **22.12 이상**(검증 환경 22.22.3), npm, pnpm **10.25.0**, Rust와 `wasm32-unknown-unknown` target, wasm-pack **0.15.0**이 필요합니다. Rust 1.96.0으로 검증했습니다. 처음에는 각 독립 프로젝트의 고정 lockfile로 설치합니다.

```sh
npm run vendor:fetch
npm ci
CI=1 HUSKY=0 pnpm --dir vendor/superdoc install --frozen-lockfile
CI=1 HUSKY=0 npm --prefix engines/docx ci
CI=1 HUSKY=0 npm --prefix vendor/pptist ci
CI=1 HUSKY=0 npm --prefix vendor/rhwp/rhwp-studio ci
rustup target add wasm32-unknown-unknown
npm run engines:build
npm run dev -- --host 127.0.0.1
```

`vendor/`는 git에 포함하지 않습니다. `vendor:fetch`는 각 엔진의 고정 upstream archive를 내려받아 SHA-256을 확인하고 `vendor-patches/<엔진>.patch`를 적용해 `vendor/superdoc`, `vendor/rhwp`, `vendor/pptist`를 만듭니다. 이미 있는 디렉터리는 건너뜁니다. `vendor/` 소스를 수정했다면 upstream archive 대비 patch를 다시 생성해 `vendor-patches/`에 커밋하세요.

```sh
npm test
npm run build
```

`engines:build`는 SuperDoc 소스와 DOCX wrapper, rhwp WASM과 Studio, PPTist를 순서대로 빌드하여 `public/engines/`에 복사합니다. 어느 단계든 실패하면 중단합니다. `build`는 이 엔진 빌드, 루트 TypeScript 검사, Vite production build를 모두 실행합니다. 엔진 빌드 전에 개발 서버만 실행하면 런타임이 없거나 오래된 상태일 수 있습니다. 실행 중 엔진 자산을 다시 게시했다면 개발 서버를 재시작하고 브라우저를 새로 고치세요.

엔진별 소스(`vendor/superdoc`+`engines/docx`, `vendor/rhwp`, `vendor/pptist`, `node_modules`·`dist`·`target`·`pkg` 제외)와 빌드 스크립트가 마지막 빌드 이후 바뀌지 않았고 `public/engines/<엔진>/index.html`이 있으면 해당 엔진 빌드를 건너뜁니다. 판단 기록은 `node_modules/.cache/pdfeditor-engines.json`에 저장합니다. 파일 경로·크기·수정 시각으로 비교하므로 의존성 재설치나 툴체인 변경 후에는 `FORCE_ENGINES=1 npm run build`로 전체 엔진을 다시 빌드하세요.

배포 단위는 **전체 `dist/`**입니다. `dist/engines/{docx,rhwp,pptx}/`의 HTML·JS·WASM과 `dist/engines/fonts/`, 엔진별 폰트를 누락하면 안 됩니다. 런타임 URL은 `/engines/docx/index.html`, `/engines/rhwp/index.html`, `/engines/pptx/index.html`이며 부모와 같은 origin에서 제공해야 합니다. WASM은 올바른 `application/wasm` MIME으로 제공하세요. 엔진마다 외부 코드·이미지·미디어·폰트를 제한하는 CSP가 적용됩니다. CDN이나 서버 변환 서비스는 필요하지 않습니다.

`./start.sh`는 `lsof`가 필요하며 production build 후 기본적으로 `127.0.0.1:3000`에서 preview를 시작합니다. 기존 산출물을 재사용해 빠르게 시작할 때는 `./start.sh --reuse-build`를 사용할 수 있습니다. 이 옵션은 소스 변경을 반영하지 않으므로 변경 후에는 기본 `./start.sh`로 다시 빌드하세요. LAN에서 접근해야 할 때만 `HOST=0.0.0.0 ./start.sh`를 사용하세요. 이미 점유된 포트의 프로세스는 종료하지 않으며, `./stop.sh`는 3000번 포트에서 실행 중인 이 프로젝트의 Vite 서버만 종료하고 다른 서비스는 그대로 둡니다. 개발 서버와 preview는 인터넷에 공개하는 운영 서버 대신 로컬 검증용으로 사용하세요.

HTTP 환경에서도 PDF 열기·복구와 글꼴 무결성 검증을 지원합니다. 원본·글꼴의 SHA-256 해시는 HTTPS와 동일하게 유지하며, Web Crypto의 `subtle`이 없는 환경에서는 `@noble/hashes`를 사용합니다. 문서·페이지·요소 ID는 `crypto.getRandomValues`로 생성한 UUID v4입니다. 이는 HTTP 전송을 보호하지 않으므로 외부에 공개하는 배포에는 HTTPS를 사용하세요.

## 편집 및 저장

- 원본 PDF는 불변 Blob으로 유지합니다. 선택만 하거나 파일명만 바꾼 문서의 PDF 다운로드는 원본 바이트 그대로입니다.
- 변경한 문서는 원본 PDF에 네이티브 텍스트와 페이지 변경을 적용하여 저장합니다. 원본에 포함된 사각형·벡터·이미지·주석은 유지하며, 화면 스크린샷으로 PDF를 만들지 않습니다.
- 선택 도구로 원본 텍스트를 클릭하거나 Enter를 누르면 바로 편집 패널이 열립니다. 글꼴·크기·색상 등 선택 범위 서식은 이 패널에서만 바꾸며, `적용`할 때 문서 undo 한 단계로 기록됩니다. 전체 문서 글꼴·크기 적용과 중복 편집 진입 버튼은 제거했습니다. 패널 안의 undo/redo는 아직 적용하지 않은 입력에만 작동합니다.
- 도구는 손 도구와 선택만 제공합니다. 활성 버튼에 마우스를 올리면 일반 버튼은 연한 회색, 검정 주요 버튼은 짙은 회색으로 바뀝니다. 비활성 버튼은 호버 효과에서 제외하고, PDF 텍스트·페이지 썸네일 선택 영역은 원본을 가리지 않는 테두리로 표시합니다. 전환은 180ms이며 모션 감소 설정에서는 전환 애니메이션을 생략합니다.
- 편집 패널은 원본 글꼴 이름·스타일과 PDF 포함 여부를 표시합니다. 지원되는 공개 라이선스 face는 `다운로드해서 적용`으로 같은 원본 글꼴을 쓰는 **현재 초안의 run만** 바꿉니다. 다른 글꼴은 유지하며, 마지막 `적용`에서 편집과 글꼴을 실행 취소 한 단계로 확정합니다. 다운로드 후 `취소`하면 문서는 바뀌지 않습니다. OS에 글꼴을 설치하는 기능은 아닙니다.
- 지원 face는 NanumGothic/NanumMyeongjo Regular·Bold, NanumGothicCoding Regular·Bold, NotoSansCJKkr 7개 굵기, ABeeZee Regular·Italic입니다. 원본과 같은 이름·스타일이어도 제작 버전이나 글자 폭이 다를 수 있으므로 미리보기를 확인하세요. 알 수 없는 글꼴·지원하지 않는 face는 다운로드 가능하다고 표시하지 않습니다.
- 선택 도구에서 페이지의 빈 곳이나 텍스트 위를 드래그하면 사각형에 걸친 원본 텍스트 객체를 한 번에 선택합니다. 기본 드래그는 선택을 교체하며, Ctrl/Cmd/Shift를 누르거나 `여러 줄 선택`을 켜고 드래그하면 기존 선택에 추가합니다. Ctrl/Cmd/Shift+클릭 또는 `여러 줄 선택` 상태의 클릭은 개별 선택을 추가·해제합니다. 드래그 선택은 시작한 페이지 안에서만 적용하며 기존 묶음은 통째로 선택합니다. 같은 읽기 흐름의 연속된 줄은 별도 버튼 없이 묶음 편집 패널에 표시되고, 안전하게 묶을 수 없는 선택은 안내와 선택 표시만 유지합니다. `복사`도 복사 가능한 텍스트를 선택했을 때만 표시합니다. 패널이 닫힌 상태에서 빈 페이지 영역을 클릭하거나 Esc를 누르면 선택이 해제됩니다.
- 여러 원본 텍스트 객체를 함께 선택하고 `하나의 객체로 묶기`를 누르면 내용을 수정하지 않고도 안전한 연속 줄을 하나의 객체로 확정합니다. 검증 실패 시 원본은 변경하지 않으며, 묶기는 실행 취소 한 단계입니다.
- 선택만 하거나 내용을 바꾸지 않은 채 패널을 닫으면 문서는 바뀌지 않습니다. 묶은 텍스트의 내용·서식·폭을 변경하여 적용하면 실행 취소 한 단계로 기록됩니다. 적용한 묶음은 클릭으로 다시 열 수 있고 서식 변경과 페이지 복제 후에도 묶음으로 유지됩니다.
- 묶음의 자동 줄바꿈은 지정한 폭 안에서 다시 배치되며, Enter로 넣은 명시적 줄바꿈은 유지됩니다. 원본의 첫 줄·이어지는 줄 들여쓰기와 줄 간격을 기준으로 배치하고, 묶음 밖의 본문이나 다음 페이지를 자동으로 밀어내지 않습니다.
- 저장·다운로드·페이지 이동은 열린 패널의 마지막 입력을 검증한 뒤 진행합니다. `취소` 또는 한글 조합 중이 아닐 때의 Esc는 적용 전 입력을 취소하며 확정된 문서는 바꾸지 않습니다. 패널을 편집하는 동안 빈 페이지 영역을 눌러도 입력을 버리지 않습니다.
- 뷰어와 편집 패널 사이의 경계를 드래그하여 패널 너비를 조절합니다. 경계에 키보드 포커스를 둔 뒤 좌우 방향키로도 조절할 수 있습니다. 좁은 화면에서는 패널이 뷰어 위에 겹쳐 표시됩니다.
- 하단 페이지·배율 바의 책 모양 아이콘으로 `두 페이지 보기`를 켜면 현재 페이지 순서의 첫 페이지(표지)는 단독으로, 이후에는 2·3, 4·5 순서로 나란히 표시합니다. 마지막에 짝이 없는 페이지는 단독으로 표시합니다. 이전·다음 버튼은 묶음 단위로 이동하며, 양쪽 페이지의 텍스트를 각각 선택해 편집할 수 있습니다. `−`·`+`는 표시 배율을 5%포인트씩 조절하며 수동 조절 범위는 25–400%입니다. `폭 맞춤`은 표시 중인 전체 페이지 폭을 기준으로 맞추며 25%보다 작아질 수 있습니다.
- 원본 PDF와 확정된 편집, 사용한 다운로드 글꼴 바이트·라이선스는 이 기기의 IndexedDB에 자동 저장됩니다. 보관함에도 함께 저장하므로 이후 복구할 때 글꼴을 다시 다운로드할 필요가 없습니다. 보관함 저장은 별도 기록이며 초안을 삭제하지 않습니다. 브라우저 데이터 삭제 시 이 기록도 사라지므로 중요한 문서는 PDF로 다운로드하세요.
- 저장 형식은 v5입니다. 이전 v2/v3/v4 초안·보관함 중 삭제된 기능의 데이터가 없는 기록은 원본 PDF·글꼴 바이트, 페이지 순서와 원본 텍스트 편집을 유지하여 변환합니다. 편집기에서 삽입한 텍스트·이미지·서명(빈 서명 자리 포함)·사각형 또는 형광펜이 들어 있는 기록은 내용을 일부 버려서 열지 않고, 전체 원본 기록을 `이전 작업 백업`으로 보존합니다. 이러한 기록은 현재 버전에서 이어서 편집할 수 없으며 JSON 백업을 다운로드할 수 있습니다. 지원하지 않는 구버전이나 형식이 잘못된 기록도 백업으로 보존하고 다른 정상 보관함 기록은 계속 표시합니다. 백업 JSON의 Blob은 MIME 타입과 base64 바이트를 포함하며 `undefined`인 선택적 필드는 생략합니다. 백업 삭제는 명시적으로 확인해야 합니다.
- 암호는 메모리에만 보관하므로 복구 시 다시 입력해야 합니다. PDF의 본문 편집·페이지 구성·복사 권한을 각각 적용합니다.

### Office 편집 및 복구

- 파일 확장자가 아니라 PDF header, ZIP package manifest, CFB stream을 검사합니다. 형식이 모호하거나 손상된 파일, 매크로 Office 형식, 암호화된 Office 컨테이너는 지원 형식으로 가장하지 않고 거부합니다.
- 공통 도구는 실행 취소/다시 실행, 굵게·기울임·밑줄, 글꼴, pt 크기, 색상, 배율입니다. 선택 범위의 혼합 값과 확인할 수 없는 값은 구분합니다. 표·문단·도형·슬라이드 등은 각 엔진의 전용 패널을 사용합니다. PDF는 기존 선택 텍스트 편집 패널을 유지합니다.
- HWP/HWPX는 rhwp 네이티브 편집을 유지하며 왼쪽 실제 페이지 미리보기 목록에서 쪽을 이동하고 목록을 접을 수 있습니다. 하단에는 이전·다음, 현재 쪽 입력/전체 쪽 수, 5%포인트 확대·축소(25–400%), 폭 맞춤, 두 페이지 보기를 제공합니다. 두 페이지 보기는 표지를 오른쪽에 두고 이후 2·3, 4·5쪽을 나란히 배치합니다. PDF 변환이나 오른쪽 편집 패널, PDF용 페이지 복제·회전·삭제·재정렬 기능은 추가하지 않습니다.
- HWP/HWPX의 PDF 스타일 상단 도구 모음은 왼쪽에 전체 페이지 격자와 네이티브 손·선택 도구를 제공하고, 바로 뒤에 굵게·기울임·밑줄·글꼴·크기·색상을 기존 알약 모양 버튼과 함께 배치합니다. 별도 서식 행 없이 좁은 화면에서는 같은 도구 모음 안에서 줄바꿈합니다. 격자에서 쪽을 선택한 뒤 `열기`를 누르거나 두 번 클릭하여 이동하고, `Escape`로 닫습니다. `여러 줄 선택` 버튼은 표시하지 않지만 네이티브 F5 키보드 선택은 유지합니다. `복사`를 누를 때만 선택 내용을 일반 텍스트로 읽어 복사하며, 지원하지 않는 선택에서는 비활성화 사유를 표시합니다. 선택 상태·복사·실행 취소·다시 실행은 오른쪽에 배치합니다.
- 홈으로 이동할 때 마지막 입력과 초안을 저장하고 같은 편집 세션을 유지합니다. 다른 문서는 후보 엔진의 첫 표시가 성공한 뒤 교체합니다. 엔진 준비를 취소하거나 열기에 실패하면 기존 문서가 남습니다.
- DOCX/HWP/HWPX 초안은 해당 형식의 native 체크포인트를 사용합니다. PPTX 초안은 PPTist 내부 문서와 Blob 자산을 함께 저장합니다. Office는 `pdfe-office-db` version 1, 기존 PDF는 `pdfe-draft-db` schema 2 / record v5로 별도 관리합니다.
- 원본 Blob과 SHA-256은 보존합니다. 수정하지 않은 다운로드는 원본 바이트 그대로이며, 수정 후에는 `_수정본` 파일로 다운로드합니다. 원래 파일을 덮어쓰지 않습니다. 보관함은 명시적 snapshot이며, Office 보관 문서를 열면 새 작업 사본을 만들고 기존 초안과 보관 문서를 유지합니다.
- 복구 목록의 `보존 원본 다운로드`는 엔진을 열지 않고 저장된 원본을 제공합니다. 암호 필요 등으로 후보 엔진이 열리지 못했더라도 저장된 원본을 받을 수 있습니다.
- 저장 실패나 용량 부족은 성공으로 표시하지 않습니다. 마지막 좋은 체크포인트를 유지하고 재시도를 제공합니다. 지원하지 않는 엔진 버전이나 손상된 기록은 원본 Blob을 포함한 이전 작업 백업으로 보존합니다. 브라우저 데이터를 지우면 초안·보관함도 사라지므로 중요한 문서는 별도 다운로드하세요.
- 보호된 DOCX와 읽을 수 있지만 저장 암호가 필요한 HWP/HWPX는 편집·수정본 저장을 허용하지 않고 보존 원본만 제공합니다. **열기 자체에 암호가 필요한 HWP/HWPX는 지원하지 않습니다.** 숨은 암호창이나 보호 해제·평문 변환으로 우회하지 않습니다.
- HWP/HWPX export가 내용 손실을 보고하면 자동 저장은 마지막 좋은 초안을 유지합니다. 명시적 수정본 다운로드는 손실 안내를 확인한 뒤에만 진행합니다.
- PPTX는 가져오기 전에 변환 편집 경고를 표시하고 원본을 보존합니다. 고급 서식·마스터·애니메이션의 완전한 보존을 약속하지 않습니다. 수정본은 PPTX로 저장하며 PDF 변환이나 이미지 평탄화를 대신 제공하지 않습니다.
- 문서의 외부 이미지·미디어는 자동으로 가져오지 않습니다. 누락·대체 글꼴과 필요한 외부 자원은 경고로 표시합니다. 없는 원본 글꼴을 같은 글꼴로 표시하지 않습니다.
- PPTX의 좁은 화면에서는 `슬라이드`·`속성` 버튼으로 기존 패널을 열고 닫으며, `화면에 맞춤`으로 슬라이드를 표시 영역에 맞출 수 있습니다. 별도 모바일 데모가 아니라 같은 편집 화면입니다. 혼합된 굵게·기울임·밑줄 선택을 누르면 전체 선택에 적용하고, 다시 누르면 전체 선택에서 해제합니다.

## 보존 범위와 제한

스캔 또는 윤곽선으로 된 문자를 OCR로 만들어내지 않습니다. 원본 글꼴이 없거나 포함된 일부 문자 외의 새 문자가 필요하면 지원되는 같은 face를 명시적으로 다운로드하거나 대체 글꼴 사용에 동의해야 합니다. 다운로드 실패 시 기존 초안을 유지하며 다시 시도할 수 있습니다. 복잡한 shaping, 세로쓰기, 클리핑·겹침 또는 Unicode 매핑이 불명확한 본문은 해당 영역의 교체만 제한하며 원본 보기와 허용된 복사는 유지합니다. 페이지 밖으로 넘치거나 다른 본문과 겹치는 편집은 적용하지 않습니다.

묶기는 같은 읽기 흐름의 연속된 원본 텍스트에 한합니다. 중간 줄을 빠뜨리거나 다른 열·쓰기 방향·이미지·표 경계 등을 가로지르는 선택은 거부할 수 있습니다. 묶음이 커져 페이지 경계나 다른 본문·이미지·요소와 겹치면 적용하지 않습니다. 자동으로 글자를 줄이거나 문서 전체를 재배치하지 않으므로 내용·폭·크기를 조정하세요.

원본 PDF의 인증서 서명은 삽입 기능과 별개입니다. 문서를 수정하면 기존 인증서 서명 검증이 유지되지 않을 수 있습니다. XFA 또는 서명 위젯 페이지는 복제하지 않으며, 일반 복제본은 원본 태그 구조에 포함되지 않습니다.

문서 바이트는 서버로 전송하지 않습니다. PDF 엔진·WASM·기본 편집용 폰트는 배포 서버의 same-origin 정적 자산입니다. 텍스트를 선택하는 것만으로 외부 글꼴을 요청하지 않습니다. `다운로드해서 적용`을 누르면 필요한 지원 글꼴과 라이선스만 GitHub의 공개 원본 저장소에서 가져옵니다. 기본 제공 face는 배포 자산을 재사용합니다. 앱 UI는 시스템 글꼴을 사용하며 외부 CSS/웹폰트를 요청하지 않습니다. 흰색·회색·검정 테마는 기존 CSS 변수와 스타일 토큰으로 구현하며 Tailwind를 추가하지 않습니다. PDF 원본의 글꼴·색상과 편집용 색상 선택은 UI 테마와 별개로 유지됩니다.

검증은 재배포 가능한 합성 문서와 동일 엔진 재열기, native ZIP/CFB 내부 검사, Chromium CDP 조합 입력으로 수행합니다. 임의의 업무 문서에 대한 완전 호환성을 보장하지 않습니다. **Windows/macOS 실제 IME 및 Microsoft Word·PowerPoint·한컴 한글 원래 프로그램 호환성은 미검증**이며, Chromium이나 동일 엔진에서 재열기한 결과와 구분해야 합니다.
